Data product contracts

Each product is a manifest: the objects and columns it exposes, its owner and steward, freshness SLA, classification, certified KPIs and endpoints (SQL, semantic view, MCP, share).

Evidence-based certification

Products are certified from your account's metadata: objects and contract columns exist, owner tag, documentation, data metric functions, masking on every PII column, on-time loads. Failures name the fix.

Internal marketplace listings

Secure contract views in a managed-access schema, a share per product and an organization listing with the data dictionary, support contact and approver — generated from the manifest, never hand-edited.

Agents on certified data

Cortex Analyst and Cortex Search agents published beside the products they use, each with its own role, a spend budget and an evaluation suite of golden questions that gates every change.

Adoption and chargeback

Consumers per product from access history, cost per product and per agent answer from Package O, and deprecation with notice for products nobody uses.

Open endpoints

Products and agents are also reachable through our MCP server and REST API, so Claude, Cursor or Cortex Code users get the same certified answers as Snowflake Intelligence users.

Nothing is listed until it passes.

Publishing emits listing and agent SQL only for items that certify on the latest snapshot; everything else is held back with its reasons. The listing manifest is generated from the product contract, so the marketplace, the semantic layer and the documentation never drift apart.

Listing and agent syntax is re-verified against current Snowflake documentation on every engagement.
